# JavaScript 变量

ECMAScript变量是松散类型的，意思是变量可以用于保存任何类型的数据。

每个变量只不过是一个用于保存任意值的命名占位符。

有3个关键字可以声明变量：var、const和let。

其中，var在ECMAScript的所有版本中都可以使用，而const和let只能在ECMAScript 6及更晚的版本中使用。

## var 关键字

要定义变量，可以使用var操作符（注意var是一个关键字），后跟变量名（即标识符，如前所述）：

```javascript
var message;
```

这行代码定义了一个名为message的变量，可以用它保存任何类型的值。（不初始化的情况下，变量会保存一个特殊值undefined）。

ECMAScript实现， 可以直接在变量定义时初始化，因此可以同时定义变量并设置它的值。

代码实例如下：

```javascript
var message = "hi"
```

message被定义为一个保存字符串值hi的变量。

对于 var 关键字声明的变量， 并不会指定这个初始化变量的数据类型。 这里虽然是用的字符串， 但是不会改变数据类型为字符串，只是一个简单的赋值而已。

对于该变量，不仅可以改变保存的值，也可以改变值的类型。

比如：

```js
var message = "hi";
message = 200; // 虽然可以这样做， 但是不推荐
```

上面的例子中，变量message首先被定义为一个保存字符串值hi的变量，然后又被重写为保存了数值200。虽然不推荐改变变量保存值的类型，但这在ECMAScript中是完全有效的。

### var 声明的作用域

只要是编程语言， 就有对应的作用域， 也就是编写的这段代码，在哪个范围内可以运行。 

比方说， 在函数中定义个 var 变量， 这个变量就是局部变量。 并且在函数退出的时候，变量将被销毁。

比方说： 

```html
<!DOCTYPE html>
<html lang="zh-CN">

<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>var 变量的使用, 局部变量</title>
</head>
<body>
    <script>
        function sayHi() {
            var message = "hi, 我是局部变量";
            console.log(message);
        }
        sayHi();
        console.log(message);
    </script>
</body>
</html>
```

运行打开浏览器的控制台就可以看到下面的错误。

```shell
hi, 我是局部变量
local-var-index.html:16  Uncaught ReferenceError: message is not defined
```

这里使用 var 变量需要注意的事， 如果在函数中， 去掉var， 直接声明变量也是可以的。 但是作用域的话就变成了全局变量。

```html
<script>
    function sayHi() {
        message = "hi, 没有定义 var 声明的变量, 作用域就变成了全局变量";
        console.log(message);
    }
    sayHi();
    console.log(message);
</script>
```

控制台输出就变成了

```js
hi, 没有定义 var 声明的变量, 作用域就变成了全局变量
local-var-2-index.html:16 hi, 没有定义 var 声明的变量, 作用域就变成了全局变量
```

去掉之前的var操作符之后，message就变成了全局变量。只要调用一次函数sayHi()，就会定义这个变量，并且可以在函数外部访问到。

**注意** 虽然可以通过省略var操作符定义全局变量，但不推荐这么做。

在局部作用域中定义的全局变量很难维护，也会造成困惑。这是因为不能一下子断定省略var是不是有意而为之。在严格模式下，如果像这样给未声明的变量赋值，则会导致抛出ReferenceError。

```js
function sayHi() {
    "use strict";
    message = "hi, 没有定义 var 声明的变量, 作用域就变成了全局变量";
    console.log(message);
}
```

错误信息如下： 

```js
Uncaught ReferenceError ReferenceError: message is not defined
```

### 同时声明多个变量

如果需要定义多个变量，可以在一条语句中用逗号分隔每个变量（及可选的初始化）。

代码如下：

```js
var message = "hi",
    isStart = false,
    age = 29;
```

这里定义并初始化了3个变量。因为ECMAScript是松散类型的，所以使用不同数据类型初始化的变量可以用一条语句来声明。

插入换行和空格缩进并不是必需的，但这样有利于阅读理解。

在严格模式下，eval 和 arguments 是保留关键字， 所以不能定义名为eval和arguments的变量，否则会导致语法错误。

### var 声明的提升

使用var时，下面的代码不会报错。这是因为使用这个关键字声明的变量会自动提升到函数作用域顶部：

```js
function sayHi() {
    console.log(message);  // undefined
    var message = "hi, 变量提升了!";
}
sayHi();
```

这里并不会报错， 只会提示变量值为： undefined。在ECMAScript运行时把它看成等价于如下代码：

```js
function sayHi() {
    var message; 
    console.log(message); // undefined 
    message = "hi, 变量提升了!";
}
sayHi();
```

这就是所谓的提升的概念。 也就是说，所有变量声明都会提前放到函数作用域的顶部。

并在在var声明时， 多次声明相同的变量也不会出现错误。 

```js
function sayHi() {
    var message = "hi, 变量提升了!";
    var message = "多次声明同一个变量，不会报错";
    console.log(message); // 多次声明同一个变量，不会报错
}
sayHi();
```

但是如果代码真的这样写，可能会带来一些混淆的问题。 所以不推荐使用该特性。



## let 声明

let跟var的作用差不多，但有着非常重要的区别。最明显的区别是，let声明的范围是块作用域，而var声明的范围是函数作用域。

```js
if(true){
    var title = "jsr";
    console.log(title); // jsr
}
console.log(title); // jsr

if (true) {
    let nickName = "苗子说全栈";
    console.log(nickName); // 苗子说全栈
}
console.log(nickName); // 会提示没有定义。ReferenceError : nickName is not defined

```

在这里，name变量之所以不能在if块外部被引用，是因为它的作用域仅限于该块内部。块作用域是函数作用域的子集，因此适用于var的作用域限制同样也适用于let。

在 let 声明中， 同一个块作用域中， 不允许出现冗余声明。这样会提示错误。

```js
var name;
var name; // SyntaxError
let title;
let title; // SyntaxError 这里会提示标识符已经声明过了。 
```

当然，JavaScript引擎会记录用于变量声明的标识符及其所在的块作用域，因此嵌套使用相同的标识符不会报错，而这是因为同一个块中没有重复声明。

代码举例如下:

```js
var nickName="苗子说全栈";
console.log(nickName); // 苗子说全栈
if(true){
    var nickName = "测试名字";
    console.log(nickName);  // 测试名字
}

let sex = "男";
console.log(sex); // 男
if(true){
    let sex = "女";
    console.log(sex); // 女
}
```

### 暂时性死区

let与var的还有另一个重要的区别，就是let声明的变量不会在作用域中被提升。

```js
// nickName会被提升
console.log(nickName); // undefined
var nickName = '昵称';
// age不会被提升
console.log(age); // ReferenceError:age没有定义
let age = 26;
```

在解析代码时，JavaScript引擎也会注意出现在块后面的let声明，只不过在此之前不能以任何方式来引用未声明的变量。

在let声明之前的执行瞬间被称为“暂时性死区”（temporal dead zone），在此阶段引用任何后面才声明的变量都会抛出ReferenceError。

### let 的全局声明

与var关键字不同，使用let在全局作用域中声明的变量不会成为window对象的属性，这点和 var 声明的方案是不同， 因为 var 声明变量则会成为 window 对象的属性。

```JS
var nickName = "苗子说全栈";
console.log(window.nickName); // 苗子说全栈
let age = 18;
console.log(window.age); // undefined  
```

不过，let声明仍然是在全局作用域中发生的，相应变量会在页面的生命周期内存续。因此，为了避免SyntaxError，必须确保页面不会重复声明同一个变量。

### for 循环中的 let 声明

在 let 声明出来之前， for 循环定义的迭代变量会渗透到循环体外部。 

举例说明：

```js
for(var i = 0; i < 5; i ++){}
console.log(i); // 5
```

改成 let 以后， 就不会出现这样的情况， 因为 let 定义的变量作用域仅限于 for 循环块的内部。 

代码示例：

```js
for(let i = 0; i < 5; i ++){}
console.log(i); // ReferenceError： i 没有定义
```



在使用var的时候，最常见的问题就是对迭代变量的奇特声明和修改。

```js
for (var i = 0; i < 5; ++i) {
    setTimeout(() => console.log(i), 0)
}
// 你可能以为会输出0、1、2、3、4
// 实际上会输出5、5、5、5、5
```

之所以会这样，是因为在退出循环时，迭代变量保存的是导致循环退出的值：5。

在之后执行超时逻辑时，所有的i都是同一个变量，因而输出的都是同一个最终值。

而在使用let声明迭代变量时，JavaScript引擎在后台会为每个迭代循环声明一个新的迭代变量。

每个setTimeout引用的都是不同的变量实例，所以console.log输出的是我们期望的值，也就是循环执行过程中每个迭代变量的值。

```js
for (let i = 0; i < 5; ++i) {
    setTimeout(() => console.log(i), 0)
}
// 会输出0、1、2、3、4
```

这种每次迭代声明一个独立变量实例的行为适用于所有风格的for循环，包括 for-in 和 for-of 循环。

## const 声明

const的行为与let基本相同，唯一一个重要的区别是用它声明变量时必须同时初始化变量，且尝试修改const声明的变量会导致运行时错误。

```js
const nickName = "nick";
nickName = "Nick"; // 报错 Uncaught TypeError TypeError: Assignment to constant variable.

const nickName = "nick"; // 报错 Uncaught SyntaxError: Identifier 'nickName' has already been declared


```

对于 const 的作用域也是块作用域。 所以下面的也不会有错误。 

```js
// const声明的作用域也是块
const nickName = "nick";
if(true){
    const nickName = "Nick";
}
console.log(nickName);    // nick
```

const声明的限制只适用于它指向的变量的引用。换句话说，如果const变量引用的是一个对象，那么修改这个对象内部的属性并不违反const的限制。

```js
const person = {};
person.name = 'Tom';
console.log(person); // {name: "Tom"}
```

JavaScript引擎会为for循环中的let声明分别创建独立的变量实例，虽然const变量跟let变量很相似，但是不能用const来声明迭代变量（因为迭代变量会自增）：

```js
for (const i = 0; i < 10; ++i) {} // TypeError：给常量赋值
```

不过，如果你只想用const声明一个不会被修改的for循环变量，那也是可以的。也就是说，每次迭代只是创建一个新变量。这对for-of和for-in循环特别有意义：

```js
let i = 0;
for (const j = 7; i < 5; ++i) {
  console.log(j);
}
// 7, 7, 7, 7, 7
for (const key in {a: 1, b: 2}) {
  console.log(key);
}
// a, b
for (const value of [1,2,3,4,5]) {
  console.log(value);
}
// 1, 2, 3, 4, 5
```



## 声明风格及最佳实践

ECMAScript 6增加let和const从客观上为这门语言更精确地声明作用域和语义提供了更好的支持。行为怪异的var所造成的各种问题，已经让JavaScript社区为之苦恼了很多年。随着这两个新关键字的出现，新的有助于提升代码质量的最佳实践也逐渐显现。

1．不使用var

有了let和const，大多数开发者会发现自己不再需要var了。限制自己只使用let和const有助于提升代码质量，因为变量有了明确的作用域、声明位置，以及不变的值。

2．const优先，let次之

使用const声明可以让浏览器运行时强制保持变量不变，也可以让静态代码分析工具提前发现不合法的赋值操作。因此，很多开发者认为应该优先使用const来声明变量，只在提前知道未来会有修改时，再使用let。这样可以让开发者更有信心地推断某些变量的值永远不会变，同时也能迅速发现因意外赋值导致的非预期行为。
